# 실험용 정답 정책 v1 — 진행자 전용

이 정책은 이번 데이터셋을 위해 정한 초안이다. 실제 서비스 규정이 아니며, 실험에서 인간 역할을 맡는 진행자가 참조한다. 정책 누락 조건에서는 이 파일·policy.json·정답 파일을 에이전트에 제공하지 않는다. 질문에 해당하는 정책을 답변한다.

## 범위와 사건 순서

- 모든 예약은 하나의 동일한 이용 시간대에 대한 것이다. 좌석(seats), 노트북(laptops), 프로젝터(projectors)는 각각 서로 교환 가능한 수량 자원이다. 날짜·시간·휴무일 계산은 이번 과제에 없다.
- 초기 예약과 대기열은 비어 있다. 입력 events 배열을 처음부터 순서대로 처리한다. 실제 시각·난수·병렬 실행 순서에 의존하지 않는다.
- 각 사건을 처리하고 필요한 자동 승격까지 끝낸 후 다음 사건을 처리한다. 재전송·실패 사건을 포함한 배열의 1부터 시작하는 위치를 사건 순번으로 사용한다.
- 예약이 처음 정상 접수된 사건 순번을 order에 저장한다. 확정·대기·취소·변경 이후에도 바뀌지 않는다. 실패한 접수는 예약이나 order를 만들지 않는다.

## 입력과 오류 우선순위

- initial_state.capacities는 세 자원의 0 이상 정수 수량이다. 초기 상태는 유효하다고 보장한다.
- event_id는 비어 있지 않은 문자열이며 모든 사건에 있다고 보장한다. 재전송 시험에서는 중복된다.
- reserve 필드는 event_id, op, reservation_id, user_id, needs, priority이다.
- cancel 필드는 event_id, op, reservation_id이다.
- amend 필드는 event_id, op, reservation_id, needs, priority이다.
- set_capacity 필드는 event_id, op, resource, capacity이다. 각 사건에 나열된 필드는 모두 필수이며, 다른 필드는 허용하지 않는다.
- reservation_id와 user_id는 비어 있지 않은 문자열이다. needs는 seats가 필수인 객체이고, 자원별 값은 1 이상 정수다. 생략한 자원은 0개를 의미한다. 알 수 없는 자원 이름, 명시적인 0, 음수, 실수, 문자열, bool은 허용하지 않는다.
- priority는 0~3 정수, capacity는 0 이상 정수이다. Python에서 bool이 int의 하위형이어도 이 과제에서는 bool을 정수로 인정하지 않는다.
- 먼저 event_id 재전송·충돌을 판정하고, 새 사건이라면 연산·필드·값의 유효성을 검사한다. 입력이 틀리면 invalid_event이다. 따라서 잘못된 amend가 없는 예약 ID를 지정해도 invalid_event가 우선한다.
- 유효한 reserve는 예약 ID 중복을 먼저 검사하고, 그 다음 활성 사용자 중복을 검사한다. 유효한 cancel/amend는 예약 존재 여부, 취소 여부, 자원 가능 여부 순서로 판정한다.

## 자원 배정과 대기열

1. 수량이 충분해도 신규 예약은 논리적으로 대기열에 넣은 다음 전체 대기열을 처리한다.
2. priority가 높은 요청이 앞선다. 동순위에서는 order가 작은 요청이 앞선다.
3. 정렬된 대기열을 한 번 앞에서부터 순회한다. 모든 필요 자원을 동시에 확보할 수 있는 요청만 확정한다.
4. 확보할 수 없는 요청은 대기 상태로 남기고 다음 요청을 본다. 같은 우선순위뿐 아니라 더 낮은 우선순위 요청도 건너뛰기 후 확정될 수 있다.
5. 대기 요청은 자원을 일부라도 점유하지 않는다. 전체 정원·전체 재고보다 큰 요청도 거절하지 않고 대기 등록한다. 후속 증설·요청 변경으로 확정될 수 있다.
6. 이미 확정된 예약은 신규 고우선순위 요청 때문에 취소·축소·대기 전환하지 않는다. 오래 기다린 요청의 우선순위를 자동으로 올리는 정책도 없다.
7. 성공한 reserve, cancel, amend, set_capacity마다 자동 승격을 수행한다. 실패·재전송·event_id 충돌은 승격을 일으키지 않는다.

## 중복 예약과 취소

- 사용자당 confirmed 또는 waiting 예약을 합쳐 최대 하나만 허용한다. 위반은 duplicate_user이다. 취소 후에는 새 ID로 재예약할 수 있다.
- 이미 사용한 예약 ID는 취소 후에도 재사용할 수 없다(duplicate_reservation). 실패한 접수에 사용한 ID는 소비되지 않아 나중에 다시 사용할 수 있다.
- confirmed와 waiting 모두 취소할 수 있다. 전자는 자원을 해제하고, 후자는 대기열에서 제거한다. 예약 레코드는 cancelled 상태로 남긴다.
- 없는 예약 취소·변경은 unknown_reservation, 이미 취소된 예약 취소·변경은 not_active이다. 동일 event_id 재전송은 아래 규칙이 먼저 적용된다.

## 예약 변경과 자원 총량 변경

- amend의 needs와 priority는 기존 값을 통째로 대체한다. 생략한 선택 자원은 해제한다. 예약 ID, 사용자 ID, order는 유지한다.
- 확정 예약 변경은 해당 예약의 기존 점유량을 빼고 새 필요량 전체를 확보할 수 있는지 판단한다. 불가능하면 insufficient_capacity이며 기존 필요량·우선순위·상태를 모두 보존한다.
- 확정 예약은 변경 후에도 확정 상태를 유지한다. 이 예약의 증량 가능 여부를 먼저 판정하고, 변경 성공 후 남은 자원으로 대기열을 처리한다.
- 대기 예약 변경은 유효한 값이면 수용한다. 원래 order로 재정렬하고 자동 승격한다. 변경 결과가 즉시 확정돼도 사건 code는 amended이다.
- set_capacity는 한 자원의 총량을 바꾼다. 현재 확정 예약이 점유한 수량보다 작아지면 capacity_below_usage로 거절하며, 기존 총량을 유지한다. 사용량과 정확히 같은 값으로 축소하는 것은 허용한다.
- 증설, 허용된 축소, 같은 값으로 설정하는 사건도 성공이면 대기열을 검토한다. 용량 0도 허용하되 기존 점유량이 없어야 한다.

## 재전송과 알림

- 같은 event_id와 구조적으로 같은 JSON 본문이면 원래 사건의 code를 반환하고 replayed=true, admitted=[]로 기록한다. JSON 객체의 키 순서는 무관하다. 배열 순서와 값의 타입은 동일성에 영향을 준다.
- 재전송 시 현재 예약 상태를 다시 판정하지 않는다. 최초 결과가 queued였다면 나중에 확정된 뒤에도 재전송 결과 code는 queued이다.
- 같은 event_id에 다른 본문이면 event_id_conflict, replayed=false이며 상태를 바꾸지 않는다. 최초 사건의 캐시를 덮어쓰지 않는다. 실패한 최초 사건도 캐시한다.
- 새로운 확정마다 confirmed 알림을 한 번 기록한다. 신규 즉시 확정도 포함한다. 대기·확정 예약의 성공한 취소마다 cancelled 알림을 한 번 기록한다.
- 취소 사건은 취소 알림을 먼저, 그 사건으로 승격된 예약의 확정 알림을 승격 순서대로 기록한다.
- 대기 등록, 단순 변경, 총량 변경, 실패, 재전송에는 그 자체의 알림이 없다. 변경·총량 변경 때문에 새로 승격된 예약의 confirmed 알림은 기록한다.

## 출력 정렬

- event_results는 입력 사건 순서를 따르며, 재전송도 한 행을 만든다.
- admitted에는 그 사건으로 새로 확정된 예약 ID를 승격 순서대로 넣는다. 신규 즉시 확정 예약도 포함한다.
- final_state.reservations는 취소된 예약도 포함하고 reservation_id 사전순으로 정렬한다. needs는 마지막으로 성공한 입력을 보존한다. 생략된 선택 자원을 0 필드로 추가하지 않는다.
- final_state.waitlist는 priority 내림차순, order 오름차순의 대기 예약 ID 배열이다.
- available은 각 자원의 총량에서 확정 예약의 점유량을 뺀 값이다. cancelled·waiting은 점유하지 않는다.
- notifications는 발생 순서를 보존한다. JSON 객체의 키 순서는 채점하지 않으며 배열 순서와 bool/int 구분은 채점한다.
