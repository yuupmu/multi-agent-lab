# 예약·대기열·자원 배정 벤치마크 v1

**150세트 · 15유형 × 10변형 · 총 1,690개 사건.** 한 세트는 독립된 초기 자원 수량과 8~18개의 순차 사건으로 구성된다. 기존 예약 취소 과제와 별도로 보존하며, 사이트의 테스트 상황에서 선택할 수 있다.

평가 입력, 정답, 제출 양식, 실험 정책, 데이터 검증 도구와 부모 프로세스에서 실행되는 채점기(score.py)를 포함한다. 실제 모델 코드는 웹 백엔드의 macOS 격리 실행기로 실행한다. 정책은 실험용 초안이며 변경 시 정답도 함께 갱신해야 한다.

## 주요 파일

| 파일 | 용도 |
|---|---|
| `evaluator/cases.json` | 독립 시나리오 150개: initial_state + events |
| `evaluator/answer_key.json` | 사건별 결과 + 최종 상태 + 알림 정답 |
| `evaluator/HUMAN_POLICY.md` | 인간 역할의 진행자가 참고할 정책·오류 우선순위 |
| `evaluator/policy.json` | 해당 정답을 생성한 정책 설정 |
| `evaluator/reference.py` | 정답 구현, 모델 입력에 제공하지 않음 |
| `score.py` | 유형별·전체·구성 요소별 채점 |
| `evaluator/coverage.json` | 유형별 개수와 사건 수 |
| `evaluator/validate_dataset.py` | 파일 무결성·출력 형식·최종 상태·알림 검증 |
| `agent/TASK.md` | 정답 정책을 제외한 함수 과제 설명 |
| `agent/OUTPUT_FORMAT.md` | 함수 반환 및 일괄 제출 형식 |
| `agent/output_schema.json` | 한 시나리오 출력의 JSON Schema |
| `agent/submission_template.json` | 150개 시나리오 ID별 빈 답안지 |

## 문제 범위와 정책 초안

공유 실험실의 **하나의 동일한 이용 시간대**를 대상으로 좌석·노트북·프로젝터를 배정한다. 여러 날짜의 일정 최적화가 아니라 사건 순서에 따른 상태 전이 문제이다.

- 높은 우선순위 먼저, 동순위는 선착순.
- 모든 필요 자원을 동시에 확보해야 확정. 대기 중에는 자원을 점유하지 않음.
- 자원이 부족한 앞 요청은 건너뛰고 뒤 요청을 검토. 낮은 우선순위로도 건너뛸 수 있음.
- 이미 확정된 예약은 고우선순위 신규 요청 때문에 밀어내지 않음.
- 취소·예약 변경·자원 증설/축소 이후 자동 승격.
- 사용자당 활성 예약은 하나. 취소된 예약 ID는 재사용 불가.
- 요청 재전송은 최초 결과를 재사용하며 자원·알림을 중복 처리하지 않음.

정확한 예외, 검증 순서, 오류 코드, 알림 순서는 HUMAN_POLICY.md에 있다. 이 정책은 사용자에게 확정받은 서비스 정책이 아닌 **데이터셋 설계를 위한 명시적 가정**이다.

## 150세트 구성

| ID 범위 | 유형 | 개수 |
|---|---|---:|
| RA-01-01 ~ RA-01-10 | 정원 경계와 연속 해제 | 10 |
| RA-02-01 ~ RA-02-10 | 동순위 선착순·큰 그룹 건너뛰기 | 10 |
| RA-03-01 ~ RA-03-10 | 우선순위·접수 순서 충돌 | 10 |
| RA-04-01 ~ RA-04-10 | 정원 초과 그룹 대기·증설 | 10 |
| RA-05-01 ~ RA-05-10 | 복수 자원의 원자적 확보 | 10 |
| RA-06-01 ~ RA-06-10 | 대기 취소·반복 취소 | 10 |
| RA-07-01 ~ RA-07-10 | 확정 예약 비선점·우선순위 변경 | 10 |
| RA-08-01 ~ RA-08-10 | 확정 예약 변경·실패 시 원상 유지 | 10 |
| RA-09-01 ~ RA-09-10 | 대기 요청 변경·선착순 보존 | 10 |
| RA-10-01 ~ RA-10-10 | 자원별 단계적 증설 | 10 |
| RA-11-01 ~ RA-11-10 | 축소 거부·자동 승격 상호작용 | 10 |
| RA-12-01 ~ RA-12-10 | 사용자 중복·예약 ID 재사용 | 10 |
| RA-13-01 ~ RA-13-10 | 재전송·동일 event_id 본문 충돌 | 10 |
| RA-14-01 ~ RA-14-10 | 타입·범위·존재 여부 오류 | 10 |
| RA-15-01 ~ RA-15-10 | 취소·변경·증설의 복합 연쇄 | 10 |

변형에서는 좌석 수(4~13), 장비 수, 그룹 크기, 우선순위 배치, 증설 폭, 잘못된 입력 타입 등을 바꾼다. **150개의 서로 다른 입력이지만 15개의 시나리오 계열을 변형한 데이터**이며, 150개의 독립적 문제 유형으로 해석하면 안 된다.

## 정답과 채점 제안

한 세트의 정답은 세 부분이다.

1. `event_results`: 각 사건의 수락·대기·거절 코드, 재전송 여부, 새로 확정된 예약 ID.
2. `final_state`: 최종 총량·잔여 수량, 취소 내역을 포함한 예약 레코드, 정렬된 대기열.
3. `notifications`: 실제 발생해야 할 확정·취소 알림의 순서.

주 지표는 세 부분이 모두 일치한 시나리오당 1점, **원점수 0~150 / 환산점수 = 원점수÷150×100**으로 한다. 객체 키 순서는 무시하고 배열 순서·타입·값은 비교한다. 시나리오 누락, 중복 ID, null 제출은 정답으로 인정하지 않는다. 사건 수가 많은 유형에 가중치가 더해지지 않도록 주 지표는 시나리오 단위로 집계한다.

보조 지표로 유형별 통과율, 사건별 결과 일치율, 최종 상태 일치율, 알림 일치율을 나눠 보고할 수 있다. 중간 자원 초과 등 모든 내부 실행 상태를 직접 채점하는 기능은 이 산출물에 없다. 이를 측정하려면 후보 프로그램의 단계별 상태 추적을 추가해야 한다.

## 검증과 실험 분리

```sh
python3 -B evaluator/validate_dataset.py
```

별도 패키지는 필요 없다. 1,690개 사건별 결과는 시나리오 작성 단계에서 명시한 기대 코드·승격 목록과 대조했다. 최종 상태·알림은 그 기대 사건 결과로부터 별도의 장부 검증기로 다시 구성해 확인한다. 이는 정답 데이터의 일관성 검사이며, 모든 가능한 입력에 대한 정책의 완전성 증명은 아니다.

정책 누락 실험에서는 에이전트에 `agent/`의 과제·출력 규격만 제공하고, `evaluator/`는 분리한다. 150개 입력과 정답을 개발 중 에이전트에게 보여주지 않는다. 빈 답안지는 형식 확인용이며 실제 평가는 함수에 입력을 주어 출력을 수집하는 방식으로 연결할 수 있다.

공개 저장소에 올릴 경우 이 세트는 공개 벤치마크가 된다. 이후 논문의 비공개 평가에는 별도의 미공개 세트를 만드는 것이 필요하다. 기존 예약 취소 과제를 삭제하지 않고 선택 항목으로 추가했다. GitHub에는 별도 게시하지 않았다.
