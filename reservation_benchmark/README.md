# 예약 취소 정책 벤치마크 v1

Python 표준 라이브러리만 사용하는 고정 100문항 채점기입니다. 웹, API 키, 모델 호출 없이 실행됩니다.

각 문항은 `(현재 시각, 예약 생성 시각, 예약 시작 시각)`의 순서 있는 세 값입니다. 따라서 엄밀히는 순서쌍이 아니라 **순서 있는 세쌍**입니다. 함수가 취소 허용 여부를 `True` 또는 `False`로 반환하면 문항당 1점, 총 100점으로 채점합니다.

## 바로 실행

이 폴더에서 다음 명령을 실행합니다.

```sh
python3 score.py evaluator/reference.py --output reports/reference.json
python3 score.py agent/solution.py --output reports/submission.json
python3 -m unittest discover -s tests -v
```

첫 명령은 정답 구현의 100/100 동작 확인입니다. 에이전트가 만든 결과가 아닙니다. `agent/solution.py`는 아직 구현하지 않은 제출 틀이므로 처음에는 0점/100개 오류가 나옵니다.

## 파일 구성

| 파일 | 용도 |
|---|---|
| `agent/TASK.md` | 에이전트에게 제공할 문제 |
| `agent/solution.py` | 에이전트가 구현할 함수 |
| `evaluator/HUMAN_POLICY.md` | 인간 역할에게만 제공할 정책 정답 카드 |
| `evaluator/policy.json` | 정책 설정 |
| `evaluator/cases.json` | 입력 100개와 유형 |
| `evaluator/answer_key.json` | 독립적으로 지정한 정답 100개 |
| `evaluator/reference.py` | 정답 구현 및 판정 이유 |
| `score.py` | 제출 함수 실행 및 총점·유형별 점수 출력 |
| `build_cases.py` | 고정 사례 재생성 및 정답 구현과 대조 |

## 정책 v1 — 사용자 확정과 임시 설계 구분

**사용자 확정:** 금요일·토요일·일요일은 정기 휴무.

**현재 실험을 실행하기 위해 정한 기본값:**

1. 한국 시간(UTC+09:00), 초 단위로 판정합니다. 실제 현재 시간은 읽지 않습니다.
2. 기본 마감은 예약 시작 **24시간 전**이며, 정확한 마감 시각도 허용합니다.
3. 기본 마감 날짜가 휴무일이면 그보다 앞선 가장 가까운 영업일의 **18:00:00**으로 당깁니다. 추가 휴일도 건너뜁니다.
4. 예약 후 **10분 이내**에는 마감이 지나도 취소할 수 있습니다. 정확히 10분도 포함합니다.
5. 이미 시작한 예약은 취소할 수 없습니다. 이는 유예보다 우선합니다.
6. 예약 생성 시각이 현재보다 미래이거나 예약 시작 이상이면 잘못된 입력으로 거부합니다.
7. 추가 휴일은 **2026-11-10, 2026-12-24**입니다. 실제 공휴일이 아닌 실험용 가상 휴일입니다.

여기서 휴무는 **마감 계산용 달력**입니다. 온라인 취소 요청 시각이나 예약 이용 날짜 자체는 휴무일이라는 이유만으로 거부하지 않습니다. 이를 바꾸면 별도 실험 조건으로 정책과 정답을 함께 다시 정의해야 합니다.

규칙 적용 순서는 **입력 검증 → 시작 여부 → 예약 직후 유예 → 마감 판정**입니다.

## 100문항 구성

| 유형 | 문항 수 |
|---|---:|
| 평일 24시간 마감 전후 | 10 |
| 마감 정확히 일치 / 1초 초과 | 10 |
| 금요일에 걸린 기본 마감 | 10 |
| 토요일에 걸린 기본 마감 | 10 |
| 일요일에 걸린 기본 마감 | 10 |
| 가상 추가 휴일에 걸린 마감 | 10 |
| 추가 휴일과 금토일이 이어지는 연속 휴무 | 10 |
| 예약 후 정확히 10분 / 1초 초과 | 10 |
| 유예와 예약 시작의 우선순위 | 10 |
| 시간 순서가 잘못된 입력 | 10 |
| **합계** | **100** |

문항의 허용 정답은 45개, 거부 정답은 55개입니다. 따라서 무조건 거부하는 제출은 55점입니다. 총점만 보지 않고 유형별 점수와 허용·거부별 정확도를 함께 비교하세요.

## 연구 실험에서 사용

- 정책 누락 조건에서는 `agent/`만 별도 작업 공간에 복사하고, 인간 역할에게 `HUMAN_POLICY.md`를 줍니다. 정답 카드 전체를 에이전트에게 주지 않고 질문한 정책에 해당하는 부분만 답합니다.
- 정책 제공 대조 조건에서는 동일 과제에 전체 정책을 추가합니다.
- 피드백 전·후의 제출을 각각 보관하고 같은 100문항으로 채점하면 점수 변화도 측정할 수 있습니다.
- 테스트별 정답/피드백은 평가 종료 후 공개하세요. 개발 중 제공하면 숨겨진 평가가 아닙니다.
- 이 폴더 분리는 보안 격리가 아닙니다. 실제 실험에서는 평가기와 정답을 에이전트가 읽을 수 없는 별도 환경에 보관해야 합니다.
- 현재 채점기는 신뢰하는 로컬 제출 코드를 실행합니다. 임의의 외부 코드 실행용 샌드박스가 아닙니다.

이 100점은 **최종 취소 판정의 정확도**입니다. 질문 적절성, A/B/C 간 피드백 전파, 목록·알림 반영은 별도의 실행 로그와 통합 테스트가 필요합니다. 또한 고정된 100문항 파일럿 한 세트로 통계적 일반화나 모델 우열이 입증되지는 않습니다.

정책을 바꿀 때 `policy.json`만 수정하지 마세요. `build_cases.py`의 경계 사례와 수동 정답도 함께 바꾼 뒤 재생성·검증해야 합니다. 기존 정답은 `policy_sha256`으로 정책과 연결되어 있어 설정만 변경하면 채점기가 중단됩니다.
